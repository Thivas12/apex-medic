# Problem and scope

Apex players can describe the same experience as lag, packet loss or
rubber-banding. A troubleshooting session needs comparable evidence and a record
of what has already been tried, including cases where the cause remains unknown.

| Decision | Current scope |
| --- | --- |
| Target user | Apex Legends player on Windows PC reporting connection symptoms |
| Supported symptoms | High latency, packet loss and rubber-banding |
| Input | Player description, classified symptom, connection type and manually entered readings/results; the API also accepts data centre and onset |
| Investigation | One question, comparison or review action at a time |
| Comparisons | Nearby data centres and the player's own background downloads/streams |
| Case memory | Stored observations, conditions, reported outcomes and timestamped updates |
| Evidence | Player-entered facts stay distinct from official guidance and project policy |
| Missing values | Preserved as unknown; zero is a measurement, not a substitute for missing data |
| Stopping behavior | Review verification, unsupported procedures, inactive cases or exhausted comparisons |
| Model role | Select reviewed supporting wording without changing the chosen action |
| Success criterion | A clear next step and preserved evidence; no assumed diagnosis or permanent fix |

This prototype is evaluated with synthetic scenarios. It has no measured
real-player resolution rate, automatic telemetry or causal diagnostic model.
